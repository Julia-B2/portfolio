# Сайт-портфолио: публикация в интернете

## Что в папке

| Файл / папка         | Назначение                                        |
| -------------------- | ------------------------------------------------- |
| `index.html`         | страница сайта                                    |
| `styles.css`         | стили                                             |
| `app.js`             | данные проектов + логика (галерея, фильтры, окно) |
| `img/full/`, `img/thumb/` | изображения (полноразмерные и миниатюры)     |
| `favicon.svg`        | значок вкладки браузера                           |

Сайт статический — сборка не нужна. Локальный просмотр: открыть `index.html`
двойным кликом либо запустить в папке `npx http-server` и перейти на
`http://127.0.0.1:8080`.

Обновление контента: изображения положить в `img/full` (+ миниатюру в
`img/thumb`), карточки и подписи править в начале `app.js` (массив `PROJECTS`).

## Вариант 1 (рекомендую): Cloudflare Pages

Быстрее всех работает в России и мире, бесплатный HTTPS, неограниченный трафик.

1. Зарегистрироваться на `dash.cloudflare.com` (бесплатный тариф).
2. Workers & Pages → Create → Pages → **Upload assets** (загрузка файлов).
3. Создать проект (например `baranova-portfolio`), перетащить содержимое папки
   `сайт-визитка` (все файлы и папку `img`) → Deploy.
4. Сайт сразу доступен по адресу `имя-проекта.pages.dev`.
5. Привязка домена: Custom domains → Set up a custom domain → ввести купленный
   домен (например `baranova.archi`). Cloudflare покажет, какие NS-серверы
   прописать у регистратора домена — прописать их в личном кабинете регистратора.
   Если домен уже в Cloudflare — привязка мгновенная; если у другого
   регистратора — либо перенести NS на Cloudflare (инструкция выше), либо у
   регистратора создать CNAME-запись `www → имя-проекта.pages.dev` и A-запись
   `@ → 192.0.2.1` с прокси Cloudflare (проще первый вариант).
6. HTTPS включается автоматически.

## Вариант 2: GitHub Pages

1. Зарегистрироваться на `github.com`, создать репозиторий
   (например `portfolio`, публичный).
2. Upload files → загрузить всё содержимое `сайт-визитка` → Commit.
3. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка
   `/ (root)` → Save.
4. Через 1–2 минуты сайт доступен: `https://логин.github.io/portfolio`.
5. Привязка домена: Settings → Pages → Custom domain → ввести домен →
   Add. GitHub покажет DNS-записи:
   - A-записи для `@`: `185.199.108.153`, `185.199.109.153`,
     `185.199.110.153`, `185.199.111.153`;
   - CNAME для `www`: `логин.github.io`.
   Эти записи создать в панели управления доменом у регистратора.
   Включить галочку **Enforce HTTPS** (появится после выпуска сертификата,
   до 24 часов).

Замечание: `github.io` из России иногда открывается медленно или нестабильно;
личный домен обычно решает проблему, но Cloudflare Pages надёжнее.

## Покупка домена

- Регистраторы: reg.ru, nic.ru, `cloud.ru` и др. — зона на выбор
  (`.ru` ~ 200–400 ₽/год, `.archi` — профессиональная зона для архитекторов,
  дороже).
- Домен — это ежегодная оплата регистратору; сам хостинг в обоих вариантах
  бесплатный.
- WHO-IS: для зоны `.ru` данные владельца не публикуются; при желании в других
  зонах включить privacy protection у регистратора.

## Чек-лист после публикации

- [ ] Открыть сайт с телефона и компьютера.
- [ ] Проверить разделы: Избранное, Проекты (фильтры), Обо мне, Контакты.
- [ ] Нажать на карточку проекта — листается галерея, работает закрытие (Esc).
- [ ] Поделиться ссылкой в мессенджере — превью-картинка подгружается.
- [ ] Проверить, что HTTPS-замок закрыт (без предупреждений браузера).

## Резервная копия

Папка `сайт-визитка` весит ~26 МБ. После публикации исходники остаются в этом
репозитории; дополнительно можно скачать копию из репозитория GitHub
(Code → Download ZIP).
